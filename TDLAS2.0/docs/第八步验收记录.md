# 第 8 步验收记录：DAQ 发现、NI/Fake 后端与 AI/AO 会话

日期：2026-10-28。工程：TDLAS2.0。本步完成 NI-DAQmx 代码和 SDK 开关构建，自动化验收全部使用 Fake/模拟后端；未执行真实设备枚举，未创建真实 AI/AO 任务，未向采集卡输出波形。

## 完成内容

1. 新增统一 `IDaqBackend` 契约，发现结果同时携带设备标识、产品类型、AI/AO 物理通道、AI 采样率/量程及 AO 量程/速率能力快照。设备名和通道不写死。
2. UI 增加“刷新 NI 设备”，枚举在后台线程运行；刷新不创建采集任务。选中设备后按能力快照动态填充 AI/AO 通道和四种波形。输出通道留空明确表示 AI-only。
3. 新增 NI-DAQmx ANSI C 后端。它在 Runtime 生产线程中创建、启动、读取、停止并清理任务；任务句柄不离开该线程。AO 使用完整周期再生缓冲区，AI 读取使用 200 ms 有界超时以响应停止。
4. 启动前同时执行结构校验和当次发现的设备能力校验：AI 通道、采样率、输入量程、AO 通道、波形、输出电压范围、AO 采样率和波形频率。未知 AO 能力不推测。
5. 新增可脚本化 Fake DAQ 后端。测试覆盖异步发现不阻塞 UI、启动失败、AI-only 不启动 AO、AI/AO 同时启动、能力越界拒绝、运行中断线和清理。故障后仍验证“源释放 → 输入关闭 → 处理排空”顺序。
6. CMake 支持 `TDLAS_ENABLE_DAQMX=OFF/ON`。新增 `Build-Daqmx-Debug.cmd` 和 `Build-Daqmx-Release.cmd`，硬件启用发布包独立输出到 `artifacts/release-package-daqmx/`，不覆盖无硬件包。

## 使用与边界

- 无硬件开发版：`Build-Debug.cmd` / `Build-Release.cmd`。硬件启用版：`Build-Daqmx-Debug.cmd` / `Build-Daqmx-Release.cmd`。
- 硬件启用发布程序为 `artifacts/release-package-daqmx/tdlas_app.exe`；目标机仍必须安装与设备匹配的 NI-DAQmx 驱动。
- 程序启动时不自动枚举、不自动采集。用户点击“刷新 NI 设备”才读取设备与能力；点击“开始采集”才创建 AI/AO 任务。
- 本步的 NI 只输出原始电压块并进入已有归档链路。扫描周期/FV/频率/光强/浓度定义仍未确认，因此不自动运行数值算法，不宣称实机测量正确性。
- 真实 AI/AO 验收尚未执行。进行实机验收前，仍需用户确认实际设备、AI 接线/通道、AO 通道和允许输出的电压/频率。
