## 2. 理解与实施决策

- 保持 C++17、Qt Widgets、Qt Charts、Multimedia 和 MSVC x64，不改为网页应用。
- 本机配置为 Qt 6.8.3、VS 2022 Build Tools、Windows SDK 10.0.26100.0；旧文档 Qt 6.11.2 路径仅作历史记录，实际安装和组件可用性在第 1 步重新检查。
- 新工程独立构建，按需迁移并审查旧版代码，迁入的源码必须位于新目录，不通过相对路径链接旧版源码。
- 保留 Core、DAQ、UI、App 的职责分离，逐步拆出 Signal、Processing、Runtime、Storage、Camera；不一次建立大量空模块，也不提前承诺 SDK ABI。
- 先做可运行布局和明确标识的模拟链路，再接入真实设备。默认启动不采集、不连接摄像头。
- 高频完整样本直接进入有界算法队列，UI 定时读取最新显示快照；峰值计算和保存不依赖 UI 刷新。
- 停止采用异步确认和排空流程；队列满、停止超时、写盘失败均须有明确状态，不静默丢数据。
- 显示窗口点数、DAQ 单次读取块大小、扫描周期点数、算法窗口和完整 FV 批次必须分离。旧字段 samplesPerCycle 不能原样承担所有语义。
- AO 保留峰值幅度定义和 AI-only；对当前对称波形按 offset±amplitude 校验，并同时检查设备能力。未知设备范围不伪造。
- 峰值吸光度、拟合峰值、FV 最大值分别建模；不能直接沿用旧拟合峰值充当规范中的观测吸光度最大值。
- 每条完整 FV 产生一条峰值记录；全负取数值最大值，空/无效批次记录 null 并断线，重复去重、乱序归位、不跨 runId 连线。
- 浓度在校准模型确认前显示“未校准”；FV 定义、光强参考、频率标定不从历史常数推断。

技术文档对旧版线程链路的描述可能落后于当前工作区（已有 SampleRouter 相关修改）。迁移前以实际源码和测试核对，不按文档重复重构。

## 12. 第六步旧算法审查迁移（2026-10-28）

按原表第 6 步完成可验证的算法迁移，不把未知物理语义伪装成测量：

- 新增独立 `tdlas_processing`。`LegacyTdlasProcessor` 复现旧 C++ 的四阶零相位低通、周期平均/对齐、边缘区四阶基线、`log(I0/I)`、旧频率偏移和 Voigt 坐标搜索；同时增加有限值、乘法溢出、窗口和下标边界检查。
- `LegacyTdlasAdapter` 在单处理线程内累计任意读取块，一次可产生零个或多个完整批次，保留会话样本范围、首尾块和批次起始时间；不完整尾部明确留在适配器，不冒充完整结果。
- `AcquisitionFrame` 新增有界阶段诊断。低通非有限输入、基线矩阵失败和不可辨识 Voigt 输入均有确定性失败阶段与原因。
- 使用直接编译的 v1.6 源码冻结合成回放参考值，新实现对 122 点吸光度摘要、观测峰位置、旧拟合峰和旧光强结果在 `1e-12` 容差内一致；来源哈希记录在 `test-data/legacy-v1.6-reference.json`。
