# 第 7 步验收记录：图表交互、峰值历史与存储导出

日期：2026-10-28。工程：TDLAS2.0。本步在第 6.5 步界面上补齐图表交互和存储链路；未开启 NI-DAQmx，未访问采集卡或摄像头。

## 完成内容

1. 所有产品图表统一使用交互视图：鼠标滚轮或 `+/-` 缩放，左键拖拽或方向键平移，悬停显示最近曲线点，`R/0` 复位，`F` 切换自动跟随。工具区增加“自动跟随”和“复位缩放”；手动导航会停止新数据改写当前观察范围。
2. 保留并验收逐完整批次的峰值历史：重复批次保留第一次结果，同序号冲突报错，乱序按序号归位；空/无效批次、缺号、单位变化和跨 runId 都产生断线。指标、图表和表格继续读取同一个不可变 `ResultSnapshot`，低 UI 刷新不会决定峰值是否接收。
3. 新增 `tdlas_storage`。模拟采集的每个已接收原始块直接进入有界后台归档队列，不经过 MainWindow。默认队列容量与算法输入容量一致；队列满、目录不可写、写入/刷新/提交失败都会令会话进入 Error。
4. 原始归档写入 `data/raw-runs/<runId>/raw.csv.partial`；会话成功停止并排空后原子命名为 `raw.csv`，同时原子提交 `manifest.json`。失败或异常停止保留 `.partial` 并在清单中标记 `incomplete`，不会显示为保存成功。
5. 峰值页启用“导出 CSV + JSON”。导出使用点击时的一致性快照，在后台线程中写入：`peak-history.csv` 面向通用分析工具，`results.json` 保留完整帧、曲线、指标、质量、批次范围和处理诊断。只有两个文件均成功提交才报告完成。
6. 安全关闭顺序扩展为：数据源释放 → 原始归档排空/完成 → SampleRouter 输入关闭 → 处理队列排空。UI 不同步等待写盘线程；导出进行中关闭窗口会等待导出完成。

## 使用与边界

- 模拟源开始后自动归档原始电压。正常停止后，状态区显示本次 `runId` 的归档目录。进程崩溃或系统断电时可能只留下 `.partial`，不能将其视为完整会话。
- “导出 CSV + JSON”只在存在完整算法批次时启用。当前产品模拟源没有已确认的扫描/FV 定义，所以它只产生原始归档，不伪造峰值或测量结果；测试中的完整批次均为合成契约夹具。
- 归档容量当前是确定的开发默认值，长期采集前仍需根据磁盘预算和实测吞吐确定保留策略、容量和文件分卷。
- NI 采集卡发现没有漏编译：TDLAS2.0 的 CMake 仍明确禁止 `TDLAS_ENABLE_DAQMX=ON`，`tdlas_daq` 当前只有模拟源。设备枚举、NI/Fake 后端和 AI/AO 会话按计划属于第 8 步。

## 运行

开发版：双击 `Run-Debug.cmd`。发布版：双击 `artifacts/release-package/tdlas_app.exe`。正常启动不会自动采集；只有用户选择模拟数据源并点击开始后才产生模拟电压和原始归档。
