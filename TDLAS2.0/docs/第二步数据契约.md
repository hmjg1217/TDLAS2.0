# 第二步：完整批次与共同结果数据源

日期：2026-10-27。本步按基础框架验收记录的“下一步”补齐数据契约、结果路由、峰值历史和界面绑定。算法、硬件、存储不在本步范围内。测试夹具中的 FV 是无量纲合成数据，只在测试程序中使用；桌面程序的模拟源继续只产生原始电压。

## 数据路径与处理接口

```text
数据源线程 → SampleRouter → 单一处理线程
                ↓               ↓ ResultProcessor：零个或多个完整 AcquisitionFrame
          原始显示快照        ResultHistory：规范化、逐批次峰值、去重、有界保留
                ↓               ↓ 不可变结果快照
                UI 定时读取 → 两处指标、两处 FV、拟合图、两处峰值图、峰值表
```

`AcquisitionRuntime::startWithResults` 接收 `ResultProcessor`，回调只在处理线程执行。处理器可在内部累计多个读取块，返回空数组表示尚无完整批次；一次调用也可以返回多个完整批次。Runtime 校验输出与输入块的 runId、设备、通道、配置修订一致后直接提交 ResultHistory，不经 MainWindow 转发、不为每批次发 UI 信号。原有 `start` 空操作回调仍可用于链路测试。

本步不推定一个读取块就是一条 FV，也不实现物理扫描周期或窗口累计算法。之后的算法适配器必须明确何时输出完整批次，以及停止时不完整尾部的处理策略。返回的批次按顺序独立提交；同一次回调后续批次失败时，先前已接收的批次保留，原始块计入 failedBlocks，不伪造整块成功。

## 字段与单位

| 类型/字段 | 约束和含义 |
|---|---|
| AcquisitionConfig.sampleRateHz | 有限正数，Sa/s；与显示窗口及读取块分离 |
| readBlockSamples / displayWindowSamples / processingWindowSamples | 分别为源读取块、最近显示窗口、预留算法窗口，均为点数 |
| scanPeriodSamples | 可选扫描周期；未知为空，不由显示点数推算 |
| queueCapacitySamples | 等待处理队列点数预算；必须能容纳一个读取块 |
| DeviceCapabilities | 显式设备身份、AI/AO 通道、波形、输入范围、采样率上下限；AO 范围与最高频率未知时为空 |
| validate(config, capabilities) | 校验设备归属与能力快照；AI-only 不要求 AO 能力。当前只提供接口和测试，尚未查询 NI 设备 |
| SampleBlock | runId、sequence、acquiredAtUtcMs（UTC 毫秒）、elapsedNs（会话单调纳秒）、设备/通道、配置修订、采样率和原始电压 |
| AcquisitionFrame | 一条完整处理批次；身份字符串非空、配置修订非零、processingVersion 非空 |
| batch.firstSampleIndex / sampleCount | 会话内原始输入样本起点和长度；长度必须大于零，不允许范围溢出 |
| batch.firstBlockSequence / lastBlockSequence | 批次所覆盖的原始读取块闭区间，前者不得大于后者 |
| sequence / acquisitionId | 当前会话的连续批次序号与批次唯一标识；不等同于读取块序号 |
| acquiredAtUtcMs / elapsedSeconds | 批次采集时刻的 UTC 毫秒与会话单调经过秒；适配器使用批次起点时刻；后者有限且非负。UTC 回拨不改变序号排序 |
| Curve.x / y | 等长坐标数组；每条曲线独立携带 xQuantity/xUnit/yQuantity/yUnit；非空曲线必须声明物理量和单位，无量纲使用 `1` |
| Curve.pointValid | 可空；非空时与坐标等长，false 的点不能参与峰值或连接曲线 |
| quality / qualityReason | Valid、Invalid、Uncalibrated；无效和未标定有原因，不能伪装有效测量 |
| processingDiagnostics | 第六步新增的有界阶段摘要；每阶段记录名称、成功状态、原因和有限非负耗时，不保存逐点日志 |
| observed / fitted / fitStatus | 同一批次观测与拟合；只有 `fitStatus == "success"` 且坐标/物理量单位匹配才叠加拟合，否则仅显示本批次观测 |
| processingVersion / baselineMethod / polarityTransform / modelId | 算法版本、基线、符号变换、拟合模型来源；本模型不自行变换 FV 方向 |
| Metrics.peakAbsorbance | 独立于 FV 最大值的吸光度最大值，缺失为 optional 空值 |
| Metrics.intensityPercent | 已由算法按确认的光强参考计算的百分比，允许超过 100%，不自行夹紧 |
| Metrics.concentration | 仅在批次有效、指标质量有效且 gasSpecies、concentrationUnit、calibrationId 全部给定时允许显示；不计算浓度 |
| PeakRecord | runId、acquisitionId、sequence、UTC/单调时间、FV 单位、质量原因、optional peakValue/peakX |

配置内存边界：显示/读取各最多 1,000,000 点；算法窗口、可选扫描周期、等待队列各最多 10,000,000 点。通用 ±10 V 输出校验继续保留，并与显式设备能力取交集；未知设备能力不能自动认定为支持输出。离散采样档位、接线模式等仍留待具体后端。

身份、单调时间或批次样本范围错误会拒收并令 Runtime 报错停源。曲线长度、点质量掩码或单位错误仍保留完整批次，但标记 Invalid、生成 null 峰值并清空测量指标。非有限指标清空；曲线中单独的 NaN/Inf/无效点只排除相应点，允许其他有效点参与峰值。

## 历史规则与容量

- 去重键为 `(runId, acquisitionId)`，首条结果保留，后续相同键不覆盖、不追加；同一 runId 下不同 acquisitionId 占用相同 sequence 则明确报冲突。
- 会话按首次接收结果的顺序排列；会话内部按 sequence 排序，UTC 只作追溯和本地时间显示。当前指标选 activeRunId 内序号最大的批次，迟到旧批次不会倒退当前指标。
- `beginRun` 保留历史并将当前结果置空，直到新会话有完整批次。`clear`（UI 复位）清空所有缓存会话；确认框明确清空范围。停止保留结果。
- 最大有效峰值保留正负，排除非有限 x/y 和无效点；并列最大值取数组中的最早位置。无效/未标定/空/全非有限批次仍占一条历史记录，peakValue 和 peakX 为空。
- null、序号缺口、会话变化、单位变化、单调时间回退均断线。迟到批次补齐序号后可恢复相邻有效批次的连线。孤立有效点显示点标记，不补零、不跨缺失连线。
- 两处峰值图调用相同分段函数，横轴均为各会话经过秒。不同会话可能共享相同经过时间范围，但不会连接。图表只显示最近有效记录的 FV 单位，避免混合单位共用数值轴；表格保留所有单位和会话。
- 默认最多保留 2000 个完整结果、2,000,000 个曲线坐标对预算（raw/observed/fitted/fv 合计；长度异常按较长数组计）。不循环覆盖、不静默丢弃；容量不足拒收、报错停源、排空原始队列，保留已接收结果。
- UI 用递增 revision 判断是否需刷新，快照通过 `shared_ptr<const AcquisitionFrame>` 共享完整曲线，不逐次复制数组。绘制降采样不修改源数据；非有限/无效点处分段，绘制预算为每条曲线的近似上限，断点多时不保证严格 5000 点。

当前缓存是有界内存保留，不是磁盘归档。没有自动保存或导出，长时间运行需要后续有界存储方案。复位后旧的只读快照若仍被调用者持有，会延长该部分内存生命周期。
