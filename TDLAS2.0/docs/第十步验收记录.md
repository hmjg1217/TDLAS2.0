## 构建与发布结果

环境：MSVC 2022 x64、Qt 6.8.3、CMake 3.30.5、Windows SDK 10.0.26100.0；DAQmx ON 构建使用本机 NI ANSI C SDK。最终结果：

| 验证 | 结果 | 证据 |
|---|---|---|
| Debug，DAQmx OFF | 12/12 CTest；10/10 原生 Step 10；启动通过 | `artifacts/debug/build.log`、`test.log`、`ui-native-step10/test.xml`、`startup-result.json` |
| Release，DAQmx OFF | 12/12 CTest；10/10 原生 Step 10；独立包启动通过 | `artifacts/release/`、`artifacts/release-package/` |
| Debug，DAQmx ON | 12/12 CTest；10/10 原生 Step 10；启动通过 | `artifacts/debug-daqmx/` |
| Release，DAQmx ON | 12/12 CTest；10/10 原生 Step 10；独立包启动通过 | `artifacts/release-daqmx/`、`artifacts/release-package-daqmx/` |
| 两份发布包完整性 | 各 77 个清单文件全部重新计算匹配 | 两包的 `SHA256SUMS.txt` |
| 最终 MSVC 编译日志 | 无 C++ 编译警告或错误 | 四种配置的 `build.log` |

本机 Windows 原生最大化内容区为 **1536×793 逻辑像素，DPR 1.25**；八张日夜/四页截图记录该实际环境。1920×1080、1600×900、1440×900、1366×768、2560×1440 与 100/125/150/200% 由 offscreen 逻辑布局测试覆盖，不能把本机截图误称作真实 1920×1080 显示器验收。

本轮首轮回归发现样式表把采集按钮的程序化 64 px 最小高度覆盖为实际 38 px，已修正为 64 px；同时禁止空图表键盘平移调用无效坐标范围。部署回归还发现 Windows PowerShell 5 的 UTF-8 文件名、`Path.GetRelativePath` 和 `Get-FileHash` 兼容性，最终改为 Unicode 码点定位说明文件、纯 ASCII 包内文件名、包根前缀校验和 .NET SHA-256 流式计算。所有修复后重新执行了相应完整构建。

最终证据目录：

- `artifacts/debug/`、`artifacts/release/`
- `artifacts/debug-daqmx/`、`artifacts/release-daqmx/`
- `artifacts/*/ui-native-step10/`
- `artifacts/release-package/`、`artifacts/release-package-daqmx/`

`windeployqt` 仍报告不能自动定位 `dxcompiler.dll`/`dxil.dll`；部署脚本随后从 Windows SDK 复制两文件，校验全部 DLL 的 PE 头，并完成移除 Qt PATH 的独立包启动，因此该提示不构成最终包缺件。DAQmx 包不私带 `nicaiu.dll`，目标机必须安装与设备匹配的 NI-DAQmx 驱动。
