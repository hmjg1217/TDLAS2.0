## 运行与构建

- `Build-Debug.cmd`：NI-DAQmx 启用的 MSVC x64 Debug 构建及完整 CTest。
- `Build-Release.cmd`：NI-DAQmx 启用的 Release 构建、测试、Qt/MSVC 运行库部署及 ZIP 打包。
- `Run-Debug.cmd`：配置 Qt PATH 后启动 Debug。
- `artifacts/TDLAS2.0-NI-DAQmx-Portable/tdlas_app.exe`：部署完成后可直接双击；移动程序时保留整个文件夹，目标机安装 NI-DAQmx 驱动。
- 默认启动最大化、日间主题、未连接；首次不会采集或连接摄像头。主题选择保存在 `data/settings.ini`。
- 验证模拟链路：左侧选择“模拟数据源（非测量）”，点击“开始采集”，进入调试页查看原始电压。停止后保留曲线；复位或再次启动前会确认替换未保存的模拟数据。尚无模拟数据导出功能。

工具安装路径统一在 `tools/local-env.json`。脚本用 Unicode Windows API 检查盘符占用，再复用或创建指向本目录的 SUBST 映射（当前为 T:）。不覆盖其他映射，不复制到旧版外部产物区。构建缓存保存盘符路径；盘符重建由下一次构建脚本完成。所有实际文件仍在 TDLAS2.0 内。

## 模块边界

| CMake 目标 | 本轮实现 | 后续接入点 |
|---|---|---|
| tdlas_core | 配置、批次/峰值契约、基础校验、最大有效峰值提取、SampleRouter | 质量细则、设备能力约束、完整历史模型 |
| tdlas_daq | ISampleSource、确定性模拟电压源 | NI discovery、AI/AO 会话、设备能力查询 |
| tdlas_runtime | 两个独立工作线程、生命周期、错误、队列统计、完整结果路由 | 真实设备阻塞/断线生命周期与存储协调 |
| tdlas_processing | 旧版窗口算法、阶段诊断、跨块完整批次适配 | 已确认扫描边界、FV/频率/光强/浓度模型 |
| tdlas_storage | 有界原始块后台归档、原子清单、峰值 CSV 与完整结果 JSON | 分卷、保留周期、磁盘预算与生产恢复策略 |
| tdlas_ui | Qt Widgets/Charts 主窗口、四页、主题、交互图表、结果绑定与导出 | 摄像会话、真实设备操作反馈 |
| tdlas_app | 程序入口、最大化启动、无采集启动自检 | 产品配置与最终部署诊断 |

Qt Multimedia 和 NI-DAQmx ANSI C SDK 是当前构建依赖。CMake 固定编译 NI 后端；缺少 `NIDAQmx.h` 或 x64 MSVC 导入库时会直接配置失败，不再生成无硬件版。

## 线程与停止

```text
数据源线程：open → read → router.submit → close
                              ├─ 有界完整块队列 → 单一处理线程
                              └─ 最新显示窗口 → UI 定时读取（最高 20 Hz）
```

块缓冲通过 shared_ptr<const SampleBlock> 传递；只有显示窗口被截取。显示按极值桶降采样，最多约 5000 点；完整处理队列不受显示窗口或 UI 刷新频率影响。后台没有逐块向 UI 发 queued signal。处理回调当前为空操作，用于核对传输、顺序和终态，不计算测量结果。

默认参数：1000 点读取块、2000 点显示窗口、100000 点预留算法窗口、100000 点队列容量。通用 AcquisitionConfig 仍不把未知扫描边界推定成旧算法窗口；`LegacyTdlasAdapter` 只在调用方提供明确算法配置时累计完整窗口。队列容量限制等待处理的点数，额外最多一个正在处理的块、一个正在生成的块和一个最新显示窗口；不能把队列容量误解为整个进程内存上限。

队列溢出拒收当前块，关闭输入并报错；已接收块继续排空。处理异常时停止数据源，异常块及尚未处理块计为 failedBlocks。运行中同时核对 `accepted = queued + processing + processed + failed`，块数和点数各自守恒；全部停止后排队及处理中必须归零，因此 `accepted = processed + failed`。rejectedBlocks 另计，不计入已接收数。当前提供聚合终态而非无界逐块日志；逐块故障区间/持久化审计属于存储阶段。

正常状态：Ready → Starting → Running → StopRequested → Draining → Stopped。自然结束可能直接进入 Draining/Stopped。任何错误会保留诊断并最终进入 Error。停止只设置原子取消标志；数据源线程先释放资源，再关闭算法输入；两线程都完成才发 stopped。UI closeEvent 延迟关闭，期间事件循环继续运行。

超过 5 秒仍未结束则进入 Error，保留窗口与活动线程，禁止复位/再次启动，等待清理完成；不强杀线程。一次停止过程只产生一次超时诊断，已有故障原因不会被超时文本覆盖。关闭快照记录 `sourceClosedOrder < inputCloseOrder < processingDrainedOrder`，并分别暴露已完成标志。ISampleSource 的 open/read 与处理器必须满足有界返回约定。未来真实驱动若不响应取消，窗口会保持错误状态；这需要在 NI 集成时验证，当前不保证故障驱动能自动恢复。Runtime 析构中的 wait 仅为非 UI 所有者最终兜底，正常 UI 关闭不走活动线程析构。

存储线程、摄像帧 mailbox 暂未创建。后续接入时必须使用有界后台路径和明确排空确认，不能把写盘或图像变换放到主窗口高频槽里。

## 数据契约与单位

| 字段/类型 | 语义 |
|---|---|
| sampleRateHz | 样本/秒，有限正数 |
| readBlockSamples | 每次数据源读取的点数 |
| displayWindowSamples | UI 最新窗口点数，不决定批次边界 |
| processingWindowSamples | 后续算法累计窗口点数 |
| scanPeriodSamples | 可选扫描周期点数；未知不推断 |
| outputAmplitudeV | 峰值幅度；已定义对称波形使用 offset ± amplitude 校验 |
| SampleBlock | runId、递增序号、UTC 毫秒、单调经过纳秒、设备/通道、配置修订、采样率与原始电压 |
| AcquisitionFrame | 一条完整算法批次；原始/观测/拟合/FV 坐标、单位、算法和质量元数据、指标 |
| PeakRecord | 一条完整 FV 的有限最大值；空/无效用 optional 空值，不能补零 |
| Metrics | 吸光度、光强百分比和浓度分别建模；缺失值用 optional，不用 0 代表未知 |

峰值提取保留负值；并列最大值取最早样本；排除非有限坐标/值和无效批次。去重、乱序归位、跨 runId 断线及 null 绘图由下一阶段历史模型实现，当前不宣称完成。

原始模拟曲线横轴是窗口内相对秒数，未标注为绝对采集时刻；状态栏单独显示最后块的本地时间。FV/拟合坐标明确“未标定/待确认”，不存在伪造的波数、吸光度、浓度数值。参考光强、FV 定义、浓度校准均待确认。

## UI 与主题

工作区按完整宽度分配 20/80，无列间外缝；小于 1440 逻辑像素时保持最小内容宽度并横向滚动。左侧 A/B/C 整体可纵向滚动；四个调试图始终为等宽等高的 2×2。四页保持单一实例，切页不会重启数据源。

`resources/design-tokens.json` 从已归档规范复制，并嵌入 Qt 资源。主题色、状态栏高度、刷新率、绘制预算由 JSON 读取；布局间距、圆角、字号和断点目前映射为对应的 Qt 常量/样式值，后续修改这些 token 时须同步布局映射。未声称所有 token 已动态绑定。

相机四项入口、峰值表和完整历史图已占位，未接入功能禁用并有文字说明。当前图表只实现原始曲线更新与复位接口，悬停、键盘选点、缩放/自动跟随、观测/拟合图例等留待图表阶段。指标保持共同的空态，实际同源结果模型尚未接入。
