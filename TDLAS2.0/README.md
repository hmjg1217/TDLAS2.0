# TDLAS2.0

独立开发目录，技术栈为 C++17、Qt 6 Widgets/Charts/Multimedia、MSVC 2022 x64、CMake、NI-DAQmx。

当前阶段：第十步最终软件回归、UI 验收、Release 部署和用户说明已完成。正常启动包含登录页、启动缓存页和管理员/客户工作台；登录目前只创建本地界面会话，不是生产认证。FV、频率、光强和浓度物理定义尚未确认，因此模拟和 NI 后端目前只生成原始电压与原始归档，不伪造测量结果。真实 NI 与真实摄像模组仍须单独现场验收。

项目只保留 NI-DAQmx 构建：使用 `Build-Debug.cmd` / `Build-Release.cmd`。Release 构建生成 `artifacts/TDLAS2.0-NI-DAQmx-Portable/` 和同名 ZIP；目标机必须是 64 位 Windows，并安装与设备匹配的 NI-DAQmx 驱动。Qt 与 MSVC 运行库已随包部署，必须整体复制发布目录，不能只复制 EXE。登录页要求非空账号和密码，并通过角色下拉框选择管理员或客户工作台；当前不校验真实凭据。

默认不枚举、不采集、不打开摄像头。模拟源可直接手动启动；在 DAQmx 版中，先点击“刷新 NI 设备”异步读取能力，选择通道后再手动开始。摄像页也只在手动刷新、选择和连接后访问 UVC 设备，图片/录像默认保存到 `data/camera/`。输出通道留空时为 AI-only。原始电压在 `data/raw-runs/<runId>/` 形成归档。由于扫描周期和 FV 定义未确认，两种数据源都不会自动生成峰值或测量指标。真实 AI/AO 与真实摄像模组尚未完成实机验收，不应将 SDK/合成帧构建通过解释为实机通过。

后续源码、构建输入、日志、测试数据、截图、发布包及开发用临时文件均放在本目录内。已安装的 Qt/MSVC/Windows SDK/NI SDK 继续作为外部工具链使用，不复制整个工具链。v1.5、v1.6 由 Git 历史和本机归档保留，不再复制进当前源码树。

首次在新电脑构建时，将 `tools/local-env.example.json` 复制为被 Git 忽略的 `tools/local-env.json`，再填写本机 Qt、CMake、Visual Studio、Windows SDK 和 NI-DAQmx SDK 路径。不要提交个人机器路径。
