# TDLAS UI 实施约束（供 Codex / 编程代理读取）

## 任务与阅读顺序
在目标项目中实现 TDLAS 桌面采集与显示界面，保持技术栈中立。开始实现前依次读取本文件、`UI_SPEC.md`、`design-tokens.json` 和 `README.md`，再检查目标项目既有架构、设备接口与测试机制。本文件作用于所在目录及子目录；放入现有仓库时，应与该仓库适用的代理指令协调。

## 规范优先级
用户明确确认的产品要求 > 本包标记为“硬性要求”的规则 > 本包建议默认值。UI_SPEC.md 定义布局、行为和数据语义，design-tokens.json 定义可复用数值与主题。若两者存在实质冲突，明确报告并请求决策，不静默改变硬性要求。目标项目采用何种框架、语言和图表库不受本包限制。

## 不得改变的要求
- 默认以最大化桌面窗口运行；基准视口 1920×1080，主工作区左 20%、右 80%。
- 左侧 A 区恰好包含规定的 11 个参数，名称和顺序不得更换；B 区为开始采集、停止采集、复位；C 区为峰值吸光度、光强百分比、气体浓度。
- 右侧四个选项卡：客户显示窗口、调试界面、峰值数据界面、摄像界面。
- 调试界面保持等宽等高的 2×2 四图：原始波形、拟合图、FV曲线、FV峰值数据记录。
- FV 曲线峰值历史表示每次采集所得 FV 曲线的最大有效峰值随时间的连续折线记录。
- 摄像界面包含拍摄、录像、数据保存、参数设置。
- 默认浅蓝白日间主题，保留深蓝夜间主题。

## 实施规则
1. 沿用项目已有技术栈与组件机制，不为满足本规范强制引入新框架。将 JSON token 映射到该技术栈的样式/主题系统，避免重复硬编码。
2. 先实现布局与模拟数据，再接入设备适配层；模拟状态必须有持续可见标识，不能把模拟值当成真实设备值。
3. 设备能力决定选项、上下限和单位。未提供型号、协议、校准模型或数值时使用“未配置/—”，不得编造设备能力、浓度、精度或业务阈值。
4. 使用结构化数据与明确单位传递波形、FV、拟合、峰值及指标；不得从曲线截图或屏幕像素反算数据。
5. 分离采集、算法、显示和保存。UI 渲染降采样不得改变峰值计算与原始数据保存；不得使用动画插值伪造测量点。
6. 所有异步命令防重入，具有进行中、成功、失败反馈；只在设备确认后进入运行或停止状态。设备异常保留已采集数据。
7. 参数验证、状态机、峰值语义、窗口适配、键盘可用性均按 UI_SPEC.md 验收。算法与单位尚未确认的项目列为待集成项，不宣称整套实机验证已通过。
8. 硬件接口缺失时仍完成可运行的模拟界面、适配边界和失败状态，交付时列明缺失依赖。不得仅生成截图替代功能界面。
9. 除非用户另行要求，不自动上传数据，不自动启动采集或摄像，不在页面打开时索取摄像权限。

## 交付要求
交付可运行入口、启动方法、token 映射说明、设备适配说明、验证结果和待确认项。逐项对照 UI_SPEC.md 验收清单，区分通过、失败、待硬件验证。视觉偏差应附实际截图与分辨率，测试结果应有可复现步骤。
