# TDLAS UI 规范文件包

版本 1.0.0 · 2026-10-22

## 包内文件
- `AGENTS.md`：Codex / 编程代理的实施指令、不可变要求与交付规则。
- `UI_SPEC.md`：完整组件布局、参数契约、图表语义、状态机、适配、可访问性和验收清单。
- `design-tokens.json`：尺寸、比例、间距、字体、双主题颜色与图表默认值。
- `README.md`：使用说明、规范边界与快速交付检查。

## 使用方法
1. 解压本包，保持四个文件位于同一目录。
2. 用 Codex 打开目标项目，将规范目录放入仓库；在任务中明确要求读取该目录的 AGENTS.md。若放在项目根目录，先合并已有 AGENTS.md，不直接覆盖项目原有指令。
3. 将以下任务文字交给 Codex（替换实际规范目录路径）：

```text
请读取 <规范目录>/AGENTS.md、UI_SPEC.md、design-tokens.json、README.md，
依据其中硬性要求，在当前项目技术栈中实现 TDLAS UI。
先检查已有架构与设备接口，然后完成布局、模拟数据、状态机和设备适配边界。
用实际数据契约区分原始信号、拟合、FV、每批次最大峰值与校准浓度。
默认日间主题，并实现夜间主题、分辨率适配与键盘操作。
FV 峰/谷方向遵从算法契约，不强制朝上；历史仍记录每批次最大有效值。
摄像界面实现拍摄、录像、数据保存、参数设置，摄像参数与左侧 11 项采集参数分开。
依照 UI_SPEC.md 验收，交付可运行入口、验证结果和待硬件确认事项。
```

技术栈不受限制，可以映射到原生桌面、跨平台桌面或浏览器宿主。JSON 中的 `layout`、`typography`、`themes` 等为通用键，需由目标项目适配读取，不应假设可直接导入某一 UI 库。

## 规范边界
用户已确认的界面结构和数据语义明确标为硬性要求。字体、精确间距、断点、默认客户页布局、状态细节等是为可执行性补齐的建议默认值，不应声称来自历史截图。当前请求之外的历史视觉资料未纳入本包。

本包不含应用源代码、硬件协议、光谱处理程序或真实测量数据。设备参数范围、FV 物理定义与单位、拟合算法、光强参考和浓度校准需要由项目提供；缺失时显示未配置或模拟标志。无需等待设备即可实现界面与模拟验收，但不得据此宣称实机测量有效。

## 快速自检
JSON 必须能由标准 JSON 解析器读取；两套主题键集合一致；文件使用 UTF-8；本地与部署端都使用相同 token 来源。1920×1080 下优先核对 20/80、11 参数顺序、四选项卡与均衡四图，再核对逐批次最大有效峰值折线、算法定义的峰/谷方向、摄像四项入口及状态行为。完整验收以 UI_SPEC.md 第 11 节为准。
